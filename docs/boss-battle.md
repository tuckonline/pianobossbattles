# Boss Battle Mode — cinematic presentation

Enable **Boss Battle Mode** under **Practice / Sight Read → Progression & recording controls**. It defaults off. Keep the existing OBS Browser Source URL `/obs/score`; the setting arrives automatically through the existing OBS snapshot transport. The live banner gains a small indicator. Banner sizing and the external keyboard-camera source do not change.

## Integration audit

- Hosted frontend: React 19 + Vite, Worker backend, D1 persistence. The repository also contains the original Next scaffold; the deployed entry is `hosted/app.tsx`.
- `hosted/sight-reading.tsx` owns the existing MIDI subscription, synchronous note buffer, start/pause/resume/stop/completion, and loop boundaries.
- `assessPractice` in `hosted/sight-library.ts` evaluates individual expected note occurrences, including chord tones and repeated pitches. `evaluateGame` in `hosted/game-core.ts` supplies stable attempt-scoped event IDs. Combat consumes those results inside `GameClient.update`, alongside XP/streak calculations, without another MIDI listener.
- The current evaluator is pitch-only: it emits correct/incorrect results, never timed misses or retrospective corrections. The reducer supports explicit missed evaluations; it does not invent them. Supporting future retrospective correction events requires canonical battle replay before enabling that evaluator capability.
- `hosted/game-client.ts` owns transient battle state and invokes the pure reducer for the existing attempt lifecycle. Combat has no authority over practice, XP, achievements, or scoring.
- `hosted/obs.tsx` publishes the battle snapshot with existing live data; `hosted/obs-state.ts` validates its shape. `/obs/score` is a read-only consumer. Reconnects restore current HP from snapshots, without replaying damage or animations.
- `hosted/obs-score.tsx` reserves a configurable 16.5% column (constrained to 16–18%). The existing Verovio ink-bounds fitter uses the remaining rectangle. This preserves its engraving and does not crop or regenerate notation on attacks. OFF uses the original full-viewport fitting path.
- Settings use the existing `gameSettings` command and D1 `game_players.settings` JSON. Saves share the existing retry loop and saved-status indicator. Old settings receive defaults; no database migration or new table is needed. Existing profile backups include the settings.

## Balance and lifecycle

`hosted/boss-config.ts` defines player HP, mistake damage, animation timing, audio, and artwork IDs. Default player HP is 30; each correct scored note always deals 1; each explicit incorrect/missed evaluation deals 4 on Normal. Mistake eight defeats the player. Boss HP equals the full expected scored-note count for the selected hand across the entire selected run, including all loops, Schmitt's final-pass cadence and selected Moonlight measures. There is no percentage discount or 100-HP cap: 20 notes = 20 HP, 100 notes = 100 HP, and 250 notes = 250 HP. Victory requires every scored note and positive player HP; a defeat remains final even if ordinary practice continues. A score with no scored notes cannot start a battle. Legacy saved target ratios and HP caps are stripped when preparing combat/settings, and old correct-note damage settings normalize to 1. No database migration or manual preference reset is required.

Starting practice creates one battle for the entire run. Boss HP equals the sum of scored notes over all selected loops (for example, 20 notes × 3 loops = 60 HP). Both HP bars, difficulty, cumulative hits/mistakes, revision and OBS battle identity carry across loops. Schmitt omits its cadence on intermediate passes and includes it once on the final pass. Each pass still saves its own scoring/XP attempt. A private scoring-attempt ID admits the next loop's evaluations, rejects late prior-loop events, and allows the same written note occurrence to count once in each loop. Pause and between-pass saving freeze the battle. Only the final loop completes it. A defeat remains final through subsequent loops; only a manually started new run resets HP. The result stays until a new run, exercise selection, or mode switch. Completion without victory reports remaining boss HP; stopping or navigating away between loops abandons the run without victory.

### Selectable difficulty

The **Boss difficulty** selector changes damage per evaluated incorrect/missed note, leaving player HP, correct-note damage, and boss HP scaling unchanged. Presets are Easy (2 damage, defeat on mistake 15), Normal (4, mistake 8), Hard (6, mistake 5), Expert (10, mistake 3), Brutal (15, mistake 2), and One-hit (30, mistake 1). Normal remains the default. The existing `bossDamagePerMistake` setting is saved in the profile; no migration is required. During an active/paused battle or its result screen, its original difficulty stays fixed. A newly selected difficulty takes effect when practice is next started manually. The OBS battle panel displays the active difficulty and damage.

Enabling during an attempt waits for the **next manually started run**. Prior notes are not replayed. Disabling removes the battle, stops presentation, and restores the score layout immediately. Changing audio/damage-number preferences does not reset HP.

Battle progress is transient and grants no extra XP/rewards/history in V1. Closing the practice page abandons the attempt through the existing recovery workflow; reopening prepares a new battle. Persistent XP, achievements, and settings retain their existing protections. OBS reconnecting alone does not restart combat.

## Art and presentation

`hosted/practice-battle-status.tsx` adds a plain live readout directly above the score in both Practice and Sight Reading. It shows player/boss HP, active difficulty, pause/readiness, and the final battle outcome. It sticks to the top while scrolling, registers as an occlusion for automatic score following, and disappears when Boss Mode is off. It reads the existing game store independently of the notation component, with no character animation, HP transitions, extra MIDI listener, or OBS dependency. Results remain until the next attempt/selection/mode change.

The canonical matchup is now Piano Blade Warrior versus Crimson Musical Colossus. Four original transparent sprite atlases provide 16 authored motion strips per character and 38 registered clips in total. Legacy saved character IDs normalize to this pair without changing balance or progress. See [the animation library](battle-animation-library.md) for the asset inventory, formats, selection rules and expansion workflow.

### Cinematic layout and visual boundaries

`hosted/battle-layout.ts` centralizes the panel/row proportions, relative character scales, normalized idle zones and anchors, minimum separation, combat overlap, return/recoil timing, background, shadows and damage-number display. Defaults allocate 10% to the player HUD, 76% to the shared arena and 14% to boss HP/status. The hero occupies the upper-left zone, with the boss 25% taller in the lower-right zone. The pair fits together without distortion. All idle poses are contained within their measured presentation envelopes; changing resolution recomputes the layout through one ResizeObserver.

`hosted/battle-stage.tsx` uses **visual artwork boundaries only**, not a physical collision engine. Idle envelopes maintain a visible gap. Attacks move toward the opposing envelope and may overlap by the configured distance; recoil moves away. Both motions return to the same idle anchors over 200 ms at normal animation speed. Interruptions start from the current rendered position. The attacker temporarily uses the front layer, then returns to the normal layer. Background/shadows stay behind the characters, impacts above them. The outer panel contains effects so they cannot cover notation; complete fighter envelopes stay within the arena.

The shared environment uses subdued navy/charcoal gradients, cyan/crimson light and ground shadows. Fresh victory/knockout outcomes appear over the arena for four seconds and then fade; only a small status label remains in the footer. Restored results do not replay the overlay. The plain website HP/outcome readout is unchanged.

Ground shadows now follow each fighter's transform and pause/return timeline, while staying behind both fighters. Correct keys select consistent attack signatures and complete, closely played written chords create progressively stronger visual strikes. Chord grouping is presentation-only; every correct scored note still deals exactly one HP and all practice remains tempo-free. See [key and chord attacks](battle-animation-library.md#key-and-chord-attacks) for mapping, grouping, transport and performance details.

On a live victory, blue flames engulf the defeated boss. On a player knockout, red flames engulf the hero. The 3.4-second canvas ending ignites, burns with a small number of embers, and fades. It is anchored to the losing character and clipped to the arena; it never covers notation or changes HP. The result remains visible afterward. Duplicate snapshots, OBS reconnects, stale outcomes, abandonment and unfinished attempts do not trigger a new ending. A new attempt or disconnect cancels an ongoing effect. Reduced motion uses a brief still aura instead of moving fire. No new sounds or asset downloads are introduced.

`hosted/boss-ui.tsx` provides HP bars and results while the separate animation director, weighted selector and canvas player handle presentation. Damage is applied before rendering. At most one visual cue is pending; rapid notes update HP immediately without creating an animation backlog. Routine attacks last 200–240ms; heavy attacks take 360–400ms. Optional synthesized cues are quiet and off by default; browser autoplay policy may require interacting with the OBS source before sound is audible. Reduced motion shows still poses. The practice controls include a visual-only character library that cannot award XP or change HP.

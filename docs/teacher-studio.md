# Teacher Studio

The dashboard reads actual courses, enrollments, completed lessons and performances. Empty states replace invented metrics. Courses owns the builder, Students owns invitation links and assignments, Analytics exposes recent results, Media stores hosted asset metadata, and Settings contains the shared MIDI setup.

Modules, lessons and blocks have keyboard-accessible move-up/down buttons. Lessons can be renamed, duplicated or deleted from drafts. Duplication generates fresh lesson and block IDs. Published versions are unchanged by draft edits. Save conflicts return HTTP 409 rather than overwriting a newer revision.

On Sites, Video, Audio and MIDI blocks include file uploads. Choose a file, click Upload, then Save draft. MP4/WebM video supports up to 1 GB (1,073,741,824 bytes) per file, using 20 MB multipart chunks with progress and automatic retries for temporary failures. Keep the page open while uploading; closing or refreshing does not resume the upload. Upload sessions expire after 24 hours and old sessions are cleaned when the teacher starts another upload. MP3/WAV/M4A/OGG audio supports up to 100 MB per file. MIDI format 0/1 files support up to 2 MB, 10,000 note/control events and one hour, with a starting tempo of 20–300 BPM. MIDI imports preserve note timing (including tempo changes), velocity and control changes for the shared player. Unsupported MIDI timelines (format 2/SMPTE) are rejected. Original files are stored privately in Sites R2; asset metadata and normalized recordings remain in D1. Uploaded assets use the course rights declaration at upload time. Students can fetch only media referenced by their enrolled version; course editors can preview their uploads before saving. Playback supports byte ranges for seeking. The standalone PostgreSQL build still uses externally hosted media URLs.

To add a block type, follow lesson-blocks.md. To add an exercise interaction template, extend `exerciseTypes` and add tested behavior in the shared player. Existing labels such as SCALE are content classifications, not generated musical content. To add scoring options, update the validated profile, scorer, author controls and tests together. Preserve old scoring algorithm identifiers for stored analyses.

New media types require asset validation, a block schema and rendering behavior. New notation behavior belongs in the canonical model and renderer adapter, not course pages. Course metadata fields must be added to `metadataSchema` and the builder; publish a new snapshot when they affect students.

Analytics extensions should aggregate version-bound performance data through an authorized service. Editors are not automatically entitled to student analytics. No advanced prediction or mastery algorithm is shipped.
